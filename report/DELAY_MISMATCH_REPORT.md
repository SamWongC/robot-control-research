# 实验二：延迟估计错误对受约束 MPC 的影响

日期：2026-11-03。性质：确定性基础对照实验，不是论文方法或实机验证。

## 问题与设置

真实输入延迟固定为 0.30 s；控制器分别假设 0、0.10、0.20、0.30、0.40 s。除此之外保持模型、权重、初始状态、参考目标及输入约束一致。

一维双积分系统，从静止的 0 m 到静止的 1 m；周期 0.05 s，运行 20 s，预测时域 40 步（2 s）。状态权重 diag(20,1)，输入权重 0.2，末端状态权重相同。不施加状态约束；仅对预测动作序列施加 -2 ≤ u ≤ 2 m/s²。这是用于方法开发的示例限制，不是根据硬件标定的极限。

使用 OSQP 求解严格凸二次规划。约束参与优化，不是将无约束动作事后截断。控制器从自己已发送的动作历史构造假设队列，不读取真实队列。真实队列初始为零，固定延迟六个周期；测量完整且无噪声，没有外扰、学习或延迟自适应。

## 结果

| 假设延迟 s | 全程位置 RMSE m | 超调 m | 收敛时间 s | 实际输入处于边界的总时长 s |
|---|---:|---:|---:|---:|
| 0.00 | 0.34406 | 0.71262 | 20 s 内未达到标准 | 15.15 |
| 0.10 | 0.24125 | 0.44473 | 20 s 内未达到标准 | 6.10 |
| 0.20 | 0.20927 | 0.16776 | 4.95 | 1.25 |
| 0.30 | 0.20951 | 0.01505 | 2.65 | 0.50 |
| 0.40 | 0.21454 | 0.03058 | 6.20 | 0.40 |

收敛标准：位置误差不超过 0.02 m 且速度绝对值不超过 0.02 m/s，此后直到模拟结束一直满足，且至少观测到 1 s 的持续满足。超调为 max(0, 最大位置-1 m)。RMSE 包含初始瞬态，统计 401 个状态样本（包含最终状态）；输入统计 400 次控制步。输入达到边界采用 1e-5 m/s² 数值容差。不是统计置信区间或对不同任务的普遍结论。

## 解释

1. 本组参数下，严重低估延迟导致持续振荡及长时间的边界输入；有输入限制后未再出现上一无约束实验的巨大加速度。
2. 正确延迟假设下，超调最小、收敛最快。高估至 0.40 s 仍收敛，但产生较慢的衰减振荡。
3. 0.20 s 的全程 RMSE 略低于正确假设（差约 0.00023 m），不能声称正确补偿在所有指标都最优。该工况超调约 0.168 m，是正确假设下约 0.015 m 的十一倍，收敛也更慢。多个指标反映不同取舍。
4. 当前样本不足以确定普遍的延迟容忍阈值，或证明低估永远比高估更差；也没有证明最终稳定性或安全性。

## 文件与复现

在项目根目录 PowerShell 运行：

```powershell
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe delay_mismatch.py
```

重建环境使用项目的 requirements-lock.txt；原 requirements.txt 保留早期最小实验依赖，运行本实验需安装 OSQP/SciPy，优先使用锁定文件。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

- delay_mismatch.py：受约束 MPC、五种假设、指标及绘图。
- test_delay_mismatch.py：预测矩阵与逐步传播一致性、独立坐标下降解核对、非激活约束时的解析解核对、真实队列延迟和输入边界检查。
- results/delay_mismatch/trajectories.png：位置、速度、实际加速度。
- results/delay_mismatch/performance.png：延迟假设与三个指标。
- results/delay_mismatch/assumed_*_steps.csv：五组逐步数据，状态为动作执行前状态，同时保存执行后状态。
- results/delay_mismatch/metrics.csv：汇总指标。
- results/delay_mismatch/summary.json：配置、依赖版本、源代码哈希与完整指标。

求解耗时仅计 solver.solve，包含热启动效果，不含建模、参数更新和日志，不可解释为整套控制器实时性能。每组 400 次优化，异常求解状态或超容差输入会使程序报错，不会静默采用失败解。
